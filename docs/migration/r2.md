# Static release downloads from R2

Public dataset reads for `YYYY-MM` releases (currently `2026-09`) use
`https://plinderdata.org/<YYYY-MM>/`. No S3 keys or Google credentials are
required. Releases with a release number, such as the legacy `2024-06/v2`, are
rejected; use an earlier `plinder` version for them. `PLINDER_MIRROR_URL` may select another HTTP(S) bucket root with
the same release layout and manifest. The local cache layout is unchanged.

## Download and cache behavior

The consumer uses cloudpathlib HTTP paths. A release-relative `manifest.jsonl.gz`
provides listing, sizes and base64 MD5 checksums. Directory traversal and file
transfers use cloudpathlib; the manifest is cached in-process.

Transfers stream into temporary files, verify size and MD5, and atomically
replace the destination. Interrupted transfers retry from the start, with up to
three attempts. They do not resume at a byte offset. Failed validation preserves
an existing destination. Parallel batches use eight workers and propagate errors.

Cached files with the expected size are reused without rehashing. Missing and
size-mismatched files are fetched again. Same-size local corruption requires a
forced refresh (`data.force_update=true`) or deletion of the affected file.
Refreshing a ZIP clears its extraction marker. `PLINDER_OFFLINE` bypasses all
network access when set to any nonempty value; unset it to return online.

Google libraries are optional for consumers and available through `plinder[data]`.
Ingestion and generation compatibility are outside this static-release change.

When a published release is updated in place, a directory download also removes
cached Parquet files under that directory that the manifest no longer lists, so
dataset readers never mix removed fragments with their replacements.

## Building the static manifest

```bash
python scripts/build_r2_manifest.py INVENTORY_DIR OUTPUT.jsonl.gz RELEASE_PREFIX
```

`INVENTORY_DIR/manifest-files.json` lists shard paths and SHA256 values. Each
compressed JSONL shard contains source rows with `name`, `size` and `md5Hash`.
The builder verifies shard checksums, rejects duplicate/invalid keys and writes
sorted records relative to `RELEASE_PREFIX` (the object-name prefix of the
release in the inventory, e.g. `PLINDER-2026-09` for the GCS staging copy). It performs no cloud I/O.

Upload changed objects first, then the manifest, then delete removed objects,
so clients never see a manifest that lists missing files. Cloudflare caches
`.gz` responses by default; upload the manifest with
`--header-upload "Cache-Control: public, max-age=60"` (rclone) so a new
manifest is served within a minute.

The current `2026-09` manifest lists 11,099 objects totaling 139,592,033,582
bytes. Its 288,878 published bytes have SHA256
`50640faf0eb855b9dc042a8e4c82127b54e7cc6479853966f3d4f55b3415eff9`. On
2026-10-04, `rclone check` against the GCS staging copy found every object
identical (MD5), and the R2 listing matched the manifest exactly.

## Initial migration validation (2026-09-14, legacy `2024-06/v2`)

These results record the original migration of the legacy release; that
release's commands (e.g. `--iteration`) predate the current CLI.

```bash
python -m pytest --noconftest tests/core/test_r2.py tests/core/test_core_config.py tests/core/test_atoms.py::test_default_sequence_alignment -q -o addopts=''
```

30 focused tests passed with Python 3.12.13, cloudpathlib 0.25.0 and NumPy 2.5.3.
They cover directory/archive access, checksums, atomic replacement, cache reuse,
forced refresh, path containment, offline behavior, interrupted-transfer retry
and integer gap penalties required by Biotite's sequence alignment API.
`--noconftest` excludes repository-wide OpenStructure-dependent fixtures. These
results do not represent full project CI or evaluation coverage.

On 2026-09-14, the revised implementation downloaded the complete release with
`plinder_download --release 2024-06 --iteration v2 --yes`: all 5,891 objects
(219,677,619,278 bytes) passed size and MD5 checks. All 1,060 system archives and
both linked-structure archives extracted successfully. Their contents total
567,902,199,349 bytes, so allow roughly 788 GB plus filesystem overhead for the
downloaded files and extracted contents together.

A deliberate process interruption preserved 1,011 completed files; restarting
the CLI reused them without changing their timestamps. A final fully cached CLI
run exited successfully in 6.44 seconds, downloaded no dataset files and left all
5,891 files unchanged. No unplanned transfer errors or retries occurred during
the full download; interrupted-transfer retry was exercised by the HTTP test
server. A separate offline reuse check passed with networking blocked.

The API tutorial, index-query notebook and system-access notebook executed all
63 code cells against the local release. A `PlinderSystem` structure smoke test
loaded the receptor and ligand for `4agi__1__1.C__1.W` successfully.

Repository-wide Ruff checks, strict typing of all 91 source files and the full
Sphinx documentation build with warnings treated as errors passed locally.
The manifest builder was checked with synthetic inventories for sorting,
checksum/duplicate rejection and preservation of an existing output on those
validation failures. These checks do not represent full evaluation coverage.

No dataset copy, permission change or public GCS retirement is part of these
commits. Existing installed clients still use GCS until upgraded.
